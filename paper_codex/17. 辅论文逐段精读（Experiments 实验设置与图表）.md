## 段落1：Experimental setup

1. 【英文原文】：

Experimental setup. Throughout all experiments, we use SCIP 8.0.0 (Bestuzheva et al., 2021) as the backend solver, which is the state-of-the-art open source solver, and is widely used in research of machine learning for combinatorial optimization (Gasse et al., 2019; Huang et al., 2022; Turner et al., 2022; Nair et al., 2020). Following Gasse et al. (2019); Huang et al. (2022); Paulus et al. (2022), we only allow cutting plane generation and selection at the root node, and set the cut separation rounds as one. We keep all the other SCIP parameters to default so as to make comparisons as fair and reproducible as possible. We emphasize that all of the SCIP solver’s advanced features, such as presolve and heuristics, are open, which ensures that our setup is consistent with the practice setting. Throughout all experiments, we set the solving time limit as 300 seconds. For completeness, we also evaluate HEM with a much longer time limit of three hours. The results are given in Appendix G.6. We train HEM with ADAM (Kingma & Ba, 2014) using the PyTorch (Paszke et al., 2019). Additionally, we also provide another implementation using the MindSpore (Chen, 2021). For simplicity, we split each dataset into the train and test sets with 80% and 20% instances. To further improve HEM, one can construct a valid set for hyperparameters tuning. We train our model on the train set, and select the best model on the train set to evaluate on the test set. Please refer to Appendix F.3 for implementation details, hyperparameters, and hardware specification.

2. 【简体中文翻译】：

实验设置。在所有实验中，我们使用 SCIP 8.0.0（Bestuzheva et al., 2021）作为后端求解器。该求解器是当前最先进的开源求解器之一，并被广泛用于“机器学习与组合优化”方向的研究（Gasse et al., 2019；Huang et al., 2022；Turner et al., 2022；Nair et al., 2020）。遵循 Gasse et al. (2019)、Huang et al. (2022)、Paulus et al. (2022) 的做法，我们只允许在根节点进行 cutting plane 的生成与筛选，并将 cut separation 的轮数设置为 1。其余 SCIP 参数均保持默认，以尽可能保证比较的公平性和可复现性。我们特别强调：SCIP 求解器的所有高级功能（例如 presolve 和 heuristics）均保持开启，这确保了我们的设置与实际应用场景一致。在全部实验中，我们将求解时间上限设置为 300 秒。为保证完整性，我们还在更长时限（三小时）下评估 HEM，相关结果见附录 G.6。我们使用 PyTorch（Paszke et al., 2019）和 ADAM（Kingma & Ba, 2014）训练 HEM。此外，我们还给出了一份基于 MindSpore（Chen, 2021）的实现。为简化流程，我们将每个数据集按 80%/20% 划分为训练集和测试集。若要进一步提升 HEM，可额外构建验证集用于超参数调优。我们在训练集上训练模型，并从训练集中选取最佳模型，在测试集上进行评估。实现细节、超参数与硬件配置请参见附录 F.3。

3. 【三梯度深度解释】：

3岁小孩级别：
这段话在说“他们怎么玩这个游戏”。他们先选了一个很厉害的“大机器人”帮忙算题，这个机器人叫 SCIP。为了公平，他们跟大家都用差不多的规则，不偷偷改奇怪按钮。每次算题都给一个闹钟，300 秒到了就停下来，不让某个方法无限算下去。然后他们还做了一个“超长版”测试，给到 3 小时，看这个方法是不是时间很长也能保持好表现。他们用电脑里的两个“做法工具”（PyTorch 和 MindSpore）来实现方法，意思是：不是只会在一种工具里跑。最后，他们把题目分成“练习题”和“考试题”（80% 训练、20% 测试），先练习，再拿没见过的题考试，看看是不是真的学会了。

中学生级别：
这一段的核心是“实验要可比、可复现、接近真实使用”。
第一，他们选 SCIP 8.0.0 作为统一后端，等于所有方法都在同一台“裁判系统”里比拼，减少平台差异。
第二，他们只在根节点做 cut 的生成和选择，而且只做 1 轮 cut separation。这样做的好处是变量更可控：你可以更清楚地把性能变化归因到“cut 选择策略本身”，而不是被多轮复杂交互掩盖。
第三，他们保留 SCIP 其他参数默认，并开启 presolve/heuristics，说明他们不是做一个脱离工业场景的“玩具设置”，而是尽量贴近真实求解流程。
第四，300 秒统一时限是常见做法，防止极端慢例子拖垮整体评估；再补充 3 小时实验，是为了回答“如果给更长时间，结论是否还成立”。
第五，训练实现上使用 ADAM + PyTorch，并补充 MindSpore 版本，能增强工程可迁移性与实现可信度。
第六，数据划分 80/20，先训练后测试，这是机器学习的标准范式；文中还提醒可以加验证集做超参数调优，说明当前方案偏向“简洁基线”，仍保留进一步优化空间。
整体上，这段不是在讲模型结构，而是在定义“比赛规则”，确保后续结果可信。

研究生级别：
从研究设计角度，这段实验设置在控制变量、外部效度与复现性之间做了有意识平衡。
第一，统一 SCIP 8.0.0 作为 backend solver，本质是把学习策略嵌入成熟 MILP 求解器生态，避免“自研求解器偏差”。引用多个既有学习优化论文，也是在建立方法学连续性。
第二，“root node + one separation round”显著降低了策略评估的时序耦合复杂度。多轮 cut 分离会引入更强的非平稳性：当前轮 cut 会改变后续 LP 松弛几何结构与候选 cut 分布，导致 credit assignment 更难。将轮数固定为 1，可把学习问题更接近 contextual decision，减少训练噪声，增强可解释性。代价是：可能低估了在深层节点与多轮 cut 下策略的长期收益。
第三，保持默认参数并开启 presolve/heuristics，是一个重要但常被忽视的选择。若关闭这些高级模块，虽然“纯策略增益”可能更显著，但实验将偏离实际部署场景；开启后，学习策略必须在强基线之上取得增益，结论更具实践说服力。
第四，双时限（300s 与 3h）隐含了两种评估视角：短时限强调“早期收敛与快速改进”；长时限更接近“最终优化质量与稳定性”。若方法在两种预算下都占优，说明策略不仅是抢早期红利，也可能改善整体求解轨迹。
第五，实现层面给出 PyTorch 与 MindSpore 两套实现，降低“框架特异性”担忧；优化器采用 ADAM 是深度 RL 中的工程稳健选择，但文中未在主段详细展开学习率、梯度裁剪、并行 worker 数等关键训练稳定性参数，因此附录 F.3 成为复现实验的必要依赖。
第六，数据划分“80/20 + train-best model selection”在表述上偏简化。严格意义上，若无独立验证集，超参数与 checkpoint 选择策略可能导致轻微估计偏差。作者也明确指出可加入 validation set，等于承认当前 protocol 是“可运行且简洁”的实践设置，而非最严格的 model selection protocol。
总体而言，这段体现的不是算法创新，而是实验方法学：通过限制自由度、统一平台、明确时限与实现细节，来支撑后续对比结果的可信解释。

## 段落2：Baselines

1. 【英文原文】：

Baselines. Our baselines include five widely used human-designed cut selection rules and a state-of-the-art (SOTA) learning-based method. Cut selection rules include NoCuts, Random, Normalized Violation (NV), Efficacy (Eff), and Default. NoCuts does not add any cuts. Default denotes the default cut selection rule used in SCIP 8.0.0. For learning-based methods, we implement a slight variant of the SOTA learning-based methods (Tang et al., 2020; Huang et al., 2022), namely score-based policy (SBP). Please see Appendix F.2 for implementation details of these baselines.

2. 【简体中文翻译】：

基线方法。我们的基线包括 5 种广泛使用的人工设计 cut 选择规则，以及 1 种最先进（SOTA）的学习型方法。这些 cut 选择规则包括 NoCuts、Random、Normalized Violation（NV）、Efficacy（Eff）和 Default。NoCuts 表示不添加任何 cut。Default 表示 SCIP 8.0.0 中使用的默认 cut 选择规则。对于学习型方法，我们实现了已有 SOTA 学习方法（Tang et al., 2020；Huang et al., 2022）的一个轻微变体，即 score-based policy（SBP）。这些基线的实现细节见附录 F.2。

3. 【三梯度深度解释】：

3岁小孩级别：
这一段在说“他们跟谁比赛”。有几位“老选手”是人们以前常用的办法：有的什么都不加（NoCuts），有的随便挑（Random），有的按规则挑（NV、Eff、Default）。还有一个“会学习的选手”叫 SBP。作者让新方法 HEM 跟这些选手一起比赛，这样大家就能看出来：HEM 到底是真的厉害，还是只是碰巧。

中学生级别：
这段的重点是“基线覆盖面够不够全面”。
他们选了两大类对手：
第一类是人工规则类（NoCuts、Random、NV、Eff、Default）。这类方法代表传统求解器里常见、可解释、稳定的策略谱系。
第二类是学习类（SBP），而且是基于已有 SOTA 思路实现的变体。
为什么这很重要？因为如果只和弱基线比，结果不可信；如果同时和“传统强规则 + 学习强方法”都比较，优势才更有说服力。
其中 NoCuts 也很关键，它相当于“零切平面干预”的参照原点，后续很多改进率指标都靠它来定义。
Default 代表 SCIP 原生配置，反映“你不改系统时的工业默认表现”。
SBP 则是当前学习式 cut selection 的代表范式：给每个 cut 打分，再按分数选。
所以这段是在告诉读者：对比对象不是随便挑的，而是覆盖了从“无策略”到“手工策略”再到“学习策略”的完整梯队。

研究生级别：
从实验对照设计看，这一段完成了 baseline taxonomy 的最小闭环。
第一，规则基线内部具有层次性：NoCuts 提供下界参照（或相对改进分母），Random 提供无信息策略参照，NV/Eff 提供经典启发式强基线，Default 提供求解器工程基线。这样的配置能够区分“是否优于随机”“是否优于经典启发式”“是否优于生产默认策略”这三类问题。
第二，引入 SBP（score-based policy）作为学习基线，实质上是在对比两种学习范式：
HEM 属于“顺序决策 + 比例与顺序联合建模”的层次化策略；
SBP 属于“逐 cut 打分 + 阈值/比例截断”的点式评分策略。
因此若 HEM 优于 SBP，可支持论文核心论点：仅靠独立打分不足以建模 cut 之间相互作用与选择顺序，序列化决策结构有增益。
第三，作者明确 SBP 是“slight variant”而非完全复刻原文方法，这在可复现实证中是常见折中，但也带来潜在威胁：性能差异可能部分来自实现细节而非范式本身。论文把实现细节放在附录 F.2，意味着审稿或复现者必须审查该附录才能判断比较是否严格等价。
第四，baseline 选择隐含了评测哲学：不是只追求“超过默认求解器”，而是要在“传统启发式 + 当代学习法”双重压力下证明一致优势。这种设计能显著提升结论的外部可信度。
简言之，这段虽然很短，但决定了后续所有结果的解释边界：HEM 的优势究竟是“超越弱对手”，还是“在强对手下仍成立”。该段给出的 baseline 组合，目标就是后者。
