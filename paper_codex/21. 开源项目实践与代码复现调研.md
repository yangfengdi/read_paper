## 2. B.pdf（HEM）官方开源项目结构与运行思路

## 2.1 PyTorch 版（官方）
仓库：`https://github.com/MIRALab-USTC/L2O-HEM-Torch`

### 目录结构（按 README 与仓库树）
- `train.py`：训练入口
- `evaluate.py`：评估入口
- `export.py`：导出策略（供 solver 推理使用）
- `src/`
  - `hem_model.py`：HEM 主模型（高层 + 低层交互）
  - `pointer_net.py`：低层 pointer network（顺序选择 cuts）
  - `dataset.py`：训练/验证数据读取
  - `trainer.py`：训练循环与优化逻辑
  - `environment.py`：与 SCIP/求解环境交互
  - `common_dtypes.py`、`utils.py` 等工具模块
- `reproduction_data/`：文中实验复现配置/辅助文件
- `scripts/`：下载或构造数据脚本

### 运行思路（端到端）
1. 先准备 MILP 数据与 cut 特征（README 指向 `ecole`、`SCIP`、`PySCIPOpt`）。
2. `train.py` 训练 HEM：
   - 高层网络先输出“应选 cut 数量/比例”；
   - 低层 pointer decoder 在该预算约束下按顺序选 cut；
   - 用分层策略梯度联合更新。
3. `evaluate.py` 在测试集统计 Time / PD integral 等指标。
4. `export.py` 导出模型，供与求解器集成部署。

### 运行思路（与 PyTorch 版同构）
- `README` 给出的标准命令是：
  - 训练：`python train.py --config_path=... --device_target=GPU`
  - 推理：`python eval.py --ckpt_path=...`
  - 导出：`python export.py --ckpt_file=... --file_format=MINDIR`
- 从源码看，核心交互是：
  - 高层：对每个 candidate cut 打分并聚合，输出 `n_cuts`（要选的数量）
  - 低层：pointer decoder 在 mask 约束下迭代选择 `n_cuts` 个 cut，得到有序子集

## 3. 你自己复现时最难写、最易出 Bug 的逻辑

## 3.1 A.pdf（WS-option，重点是 Wake-sleep）
最容易出 Bug 的点：
- `sleep -> wake` 切换时参数冻结/解冻边界不清：容易误更新高层 Q 或误停更低层策略。
- 双层时间尺度错位：高层一步对应低层多步，回报汇总区间（option 终止边界）易错。
- 经验回放污染：sleep 阶段“平均策略轨迹”和 wake 阶段“联合策略轨迹”混存会导致分布漂移。
- 终止信号编码错误：论文把下传 option 简化为二值继续/终止，若与预算计数不同步会出现 off-by-one。

### A.pdf 核心机制伪代码（Wake-sleep）
```python
# Pseudocode: WS-option wake-sleep training
init high_policy_piI, high_QI
init low_policy_piII, low_QII
init replay_sleep, replay_wake

for epoch in range(E):
    # ---- Sleep stage: stabilize lower layer first ----
    freeze(high_policy_piI, high_QI)
    for ep in range(E_sleep):
        traj = rollout_with_average_budget_strategy(env, low_policy_piII)
        replay_sleep.add(traj.low_level_transitions)
        # TD update for intra-option policy/value
        update_low_level_TD(low_policy_piII, low_QII, replay_sleep)

    # ---- Wake stage: joint but controlled co-training ----
    unfreeze(high_policy_piI, high_QI)
    for ep in range(E_wake):
        traj = rollout_with_hierarchical_policy(env, high_policy_piI, low_policy_piII)
        replay_wake.add(traj)

        # high level: MC/return over option segments
        high_batch = build_high_level_segments(traj)   # each segment: one budget decision -> cumulative return
        update_high_level_MC(high_policy_piI, high_QI, high_batch)

        # low level: TD on primitive node-selection transitions
        low_batch = build_low_level_steps(traj)
        update_low_level_TD(low_policy_piII, low_QII, low_batch)
```

## 3.2 B.pdf（HEM，两层交互）
最容易出 Bug 的点：
- 高层输出 `n_cuts` 与低层 decode 长度不一致（越界、空序列、mask 全 False）。
- 不放回选择约束：pointer 每步选完必须更新 mask，重复选择会直接破坏训练信号。
- 分层 log-prob 拼接：总策略梯度要同时包含高层与低层对同一回报的贡献，符号和 detach 处理常错。
- 变长批处理：不同样本 candidate 数不同，padding/mask 若不一致会引发 silent bug（结果退化但不报错）。

### B.pdf 核心机制伪代码（HEM 两层交互）
```python
# Pseudocode: HEM hierarchical interaction
# input: candidate cut features X, action mask M

# higher-level policy: decide how many cuts to select
h_logits = HighLevelNet(X, M)              # shape: [B, N] or pooled stats
n_cuts = sample_num_cuts(h_logits, M)      # integer per instance

# lower-level policy: pointer decoding with length = n_cuts
selected = []
logp_low = 0.0
mask = M.clone()
state = init_decoder_state(X)

for t in range(max(n_cuts)):
    idx_t, lp_t, state = PointerStep(X, state, mask)
    selected.append(idx_t)
    logp_low += lp_t
    mask = mask.scatter(dim=1, index=idx_t, value=False)  # no replacement

# hierarchical objective
logp_high = log_prob_num_cuts(h_logits, n_cuts)
logp_total = logp_high + logp_low
loss = -(advantage_or_return * logp_total).mean()
update_all_parameters(loss)
```

## 4. 复现建议（面向“可运行”）
- 先跑 B.pdf 的官方 PyTorch 版最稳：生态依赖（SCIP/PySCIPOpt/ecole）资料更多，调试成本低于从零写。
- 再做 A.pdf 的“最小可运行复现”：先固定高层为平均预算策略，只训练低层；再引入 wake 阶段联合训练。
- 对两篇都建议先写“单 batch 单 episode 的断言测试”：
  - 张量维度、mask 逻辑、终止条件、回报分段是否与理论一致。
